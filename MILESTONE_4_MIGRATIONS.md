# Milestone 4 — Alembic Database Migrations

TerraSync now uses Alembic for schema version management.

## New database

From `backend/`:

```powershell
python -m app.db.migrate upgrade
```

This creates all M1-M4 tables and records the current Alembic revision.

## Existing M1-M3/M4 development database

Older TerraSync builds used `Base.metadata.create_all()` and therefore have no
`alembic_version` record. Adopt such a database once:

```powershell
python -m app.db.migrate bootstrap
python -m app.db.migrate upgrade
```

The bootstrap does not drop existing tables or rows. It creates only missing
additive M4 configuration tables, validates the expected table set, and stamps
the Alembic baseline.

Back up a production database before any schema operation.

## Status / production check

```powershell
python -m app.db.migrate status
python -m app.db.migrate check
```

Production API startup fails fast when the database revision is behind the
application. It does not silently change the production schema.

Development/demo startup can automatically upgrade or adopt a legacy local
database when `AUTO_MIGRATE_DEVELOPMENT=true`.

## Future schema changes

Create a new revision after modifying SQLAlchemy models:

```powershell
python -m alembic revision --autogenerate -m "describe_change"
python -m alembic upgrade head
```

Review every autogenerated migration before committing it.
